## proof_c_text.bend under --verdict (for the lead)

- The overflow is in the `False` branches of `L1.g` .. `L7.g`: the inline tuple
  `(l, (t, (False{}, ({==}, (hok, {==})))))` against `WR(.., TXT(...))`. Its last `{==}`,
  `Bool.pick(String, False{}, NR.chars(WW.V(l, t)), TXT(..)) == TXT(..)`, makes the kernel normalize
  the whole text. The same tuple against an abstract text passes.
- Fix (tested on the copy: the file checks, and passes `--verdict`): one lemma `wrF` stating the tuple
  for any text `x`, and each `False` branch calls `wrF(bl, bt, wl, wt, l, t, TXT(bl, bt, bd, wl, wt,
  at, e0, e1, e2, e4, lf, q, rs, as), hok)`. The diff (79 lines) is in my scratchpad as
  `proof_c_text_verdict.diff`; I did not edit the file.
