1. **Blocker — `sample_value` and `split_format_values`, [notes/split.md:1352](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:1352), law at 1634.** The law is false. For FORMAT `AD`, sample `1,2,3`, and a nonexistent sample index, `sample_value` returns `Some{""}`. The output observation becomes `Some{[""]}`, while `lifted(NumR, …, [""])` is `None`. Bend evaluation confirmed these results. **Fix:** look up the sample column with `List.get`, returning `None` when absent.

2. **Blocker — splitting laws, [notes/split.md:1488](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:1488).** A splitter that always returns `Whole` satisfies all 13 laws: the laws concerning `Pieces` become vacuous, while `split_valid` and `split_change` concern the independent `singles` function. Nothing requires a supported multiallelic line to split or an invalid one to receive its specified refusal. **Fix:** add laws defining when splitting succeeds and when each refusal occurs, and connect the returned pieces to the variants whose changes are preserved.

3. **Blocker — value and genotype observations, [notes/split.md:1587](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:1587).** The value laws exclude whole-field `.`, without another law preserving it. `info_entry` observes only the first duplicate key, leaving later entries unconstrained despite the promise to split every occurrence. Also, `gt_alleles` interprets arbitrary invalid text as missing, so a corrupted missing allele could satisfy `split_gt` and `split_phase`. **Fix:** cover missing values explicitly, quantify over INFO entry occurrences, and require syntactically valid output GTs.

4. **Should fix — Number G ploidy, [notes/split.md:264](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:264).** Count alone does not establish sample ploidy. With two ALTs, `GT:PL=0/2:7,8,9` produces diploid GTs with two PL values. Both the draft and bcftools 1.24 accept this; it is another bcftools guess missing from the differences table. **Fix:** check G cardinality against known GT ploidy, define the missing/absent-GT policy, and describe unsupported polyploid G vectors as a scope limitation rather than inherently erroneous data. The diploid index `k(k+1)/2+j` and haploid selection `[0,i]` are correct.

5. **Should fix — refusal precedence, [notes/split.md:205](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:205).** An in-scope unknown chromosome with an undefined INFO tag now succeeds under `-m -any -c w`; without splitting it stops with UNKNOWN_CHROM. I confirmed this by evaluation. A recoverable split error should not suppress an existing fatal site error. **Fix:** preserve mandatory site failures when handling `Unsplit`; this does not require normalizing the whole multiallelic variant first.

6. **Should fix — missing header Number, [notes/split.md:250](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:250).** Treating an absent or unrecognized Number as `NumOther` silently copies potentially allele-dependent data. That contradicts the justification for UNDEFINED_TAG: the allele assignment is unknown in either case. **Fix:** distinguish fixed counts and `.` from missing, invalid or unsupported Number declarations, and refuse the latter when splitting requires their interpretation.

7. **Should fix — String implementation and proof plan, [notes/split.md:342](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:342).** Calling the specification directly carries a foreseeable cohort bottleneck: `Got.join.go` repeatedly appends to the accumulated String, making construction quadratic in the number of sample fields. The repository already records severe String-path costs. **Fix:** use linear output construction and benchmark scaling with sample count, ALT count and split density before investing in the full refinement proofs. Keep the cohort comparison, but add a dense multiallelic stress case.

8. **Minor — window explanation, [notes/split.md:322](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:322).** Moving left by at least `-w` does not necessarily cause UNSORTED; stopping depends on violating the order of records already written. **Fix:** describe the actual order check. The existing `no_unsorted` law gives a sufficient condition for avoiding that error, not its converse.

9. **Minor — phase explanation, [notes/split.md:224](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:224).** The statement overstates phase loss. Preserved allele order and copied PS can retain phase across the resulting records. **Fix:** distinguish loss of original record membership from retained haplotype assignment.

10. **Minor — reviewer decisions and parser contract, [notes/split.md:392](/home/luisc/Work/bend-projects/framebender-split/notes/split.md:392).** My choices: retain default `0` for bcftools compatibility; retain warned, unsplit passthrough under `-c w`, subject to item 5; retain UNDEFINED_TAG despite its practical rejection of headerless annotations; accept `AD=.`; and add `biallelic_run` plus whole-run backward compatibility without `-m`. State value laws as “REF and this ALT” and “REF/REF, REF/ALT, ALT/ALT,” keeping index arithmetic explanatory.
