# GPT law review: --threads

1. **Should fix — [draft `law threads`]( /home/luisc/Work/bend-projects/framebender-threads/notes/threads.md:303).** Prefix insertion does not directly express independence of the effective N. With `rest = ["-f","r.fa","--threads","8","in.vcf"]`, changing the inserted N still runs with 8. The drafted parser plus `machine` does guarantee equal results at every accepted position, but the new law obscures that. Prefer equality with a grammar-aware removal of all thread-option pairs, for accepted command lines. Keep the supporting parser fact a lemma; it needs no separate science law.

2. **Should fix — [“only speed would change”]( /home/luisc/Work/bend-projects/framebender-threads/notes/threads.md:59).** Different thread counts and read depths can change memory exhaustion and therefore actual output or exit status; [the existing contract explicitly excludes runtime exhaustion]( /home/luisc/Work/bend-projects/framebender-threads/MACHINE.bend:200). Qualify “never changes output” by the existing byte, plain-FASTA and trusted-driver/runtime assumptions. My preference is documented `+RTS --threads N -RTS` initially. A constructor can be reviewed separately, but its platform limitations and overriding runtime settings contradict the unconditional “at most N” promise.

3. **Should fix — [draft `Args.threads`]( /home/luisc/Work/bend-projects/framebender-threads/notes/threads.md:276).** This accessor ignores the command, `ok`, and pending-value state: `["wrong","--threads","129"]` returns `Some{129}`, and a trailing incomplete occurrence can leave an earlier count. Thus the driver cannot assume this function supplies a validated 1–128 count. Specify that sizing happens only after successful `Args.parse`, or make the accessor validate the completed command.

4. **Minor — [compatibility claim]( /home/luisc/Work/bend-projects/framebender-threads/notes/threads.md:18).** The grammar is deterministic, all nine drafted examples are consistent, and commands without the option retain exactly the old `Cfg`, including argument order and spelling. `-f --threads` remains a recorded path; a missing thread value is rejected. However, usage output changes even without `--threads`. Restrict byte-for-byte compatibility to accepted invocations. Also clarify that “last counts” requires every occurrence to be valid: `--threads 0 --threads 8` remains an error.

5. **Minor — [header and range decisions]( /home/luisc/Work/bend-projects/framebender-threads/notes/threads.md:399).** Approve omitting recognized thread-option pairs from the header while retaining literal path values. Retain 1–128 and reject 0: omission already selects the default, and an unlimited value would permit unreasonable read-ahead. Describe 128 as the selected resource-policy limit, based on the runtime limitation stated in the proposal. For scientists, the clearest wording is: “For accepted commands within the machine contract, changing or removing thread options preserves paths, stdout bytes, messages and exit code.”
