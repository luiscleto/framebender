The term `(VCF length + 1)^2` under `-m` is large enough for a per-record line allowance plus the extra hand-outs, and `splits` matches the parser. The fit paragraph, as written, is not yet something to prove from. Two corrections, then it is.

1. **Should fix.** `notes/split.md`, the fit: "R + 2k + 13 ≤ L" and "a = 1 + k ≤ (L − R − 11) / 2". That count gives a byte to ID, QUAL, FILTER and INFO, and a final LF. `Rec.malformed` does not require those four fields, and `Text.lines` gives a last line no LF when the file has none. Shortest splittable line, no LF: `C<TAB>1<TAB><TAB>A<TAB>C,G<TAB><TAB><TAB>` (13 bytes). R = 1, k = 2, so R + 2k + 13 = 18, which is not ≤ 13. **Fix:** minimum file length is R + 2k + 8 with no LF (7 tabs, a non-empty CHROM, a POS digit, REF, k non-empty ALTs and k − 1 commas), R + 2k + 9 with LF, and one more byte for CR LF. From R + 2k + 8 ≤ L: 2a + R ≤ L − 6 and a ≤ (L − 7) / 2, so 2aR ≤ ((L − 6) / 2)^2 ≤ L^2/4 and a(2F + 6) ≤ L(F + 3) still hold for every splittable line. Checked for every R ≥ 1 and k ≥ 2 on that minimum. CR LF only adds the terminator byte (that CR is not in the body, so it is not `BAD_CR`, and the line can split). `*` and a symbolic ALT are one non-empty allele, the same minimum. A line that `-c w` passes through is `Unsplit`: one verdict on the whole line (`ms.parts.k`, `slow.parts.k` in `norm_seq.bend`), so one LA, not one per ALT. A piece that cuts a line does not add a line: `Text.lines` runs on the concatenation, and the square depends on V.

2. **Should fix.** `notes/split.md`, the fit: "The existing term (V + 1)(F + 3) covers V(F + 3)" and "the rest of the bound is used as before." `(V + 1)(F + 3)` is already tight in the budget notes (`notes/bytes_proofs_budget.md`, "How out_len closes the start bound"): wants take (F + 2)(V + 1) and hand-outs take the remaining V + 1, with `args_len` and the `+ 3` beside them. Putting V(F + 3) of that term onto a(2F + 6) leaves F + 3, which is the old hand-out slot only when the file is short. **Fix:** give those |vcf| + 1 hand-out steps to the square as well as V^2/4 and the output growth V^2/512 + V/23. The slack against (V + 1)^2 is then at least F + 3 (3 when the FASTA is empty), at every V. The term stays (V + 1)^2. The "+ 22 bytes" step is not the hole: a left-shift keeps allele length (the new base replaces the last, `shifted` in `tan.bend`), and `end_ok` stops a short `END` from being rewritten into a long one, so a normalized record does not grow by an unbounded END. Pre-charging a = 1 + k (the input line and each record) is the right envelope: the line's LA is in the sum until the split, and the records are then charged a full LA each.

A constant factor on (V + 1)(F + 3) does not: the REF part grows with the square of the line, and that term grows with the line times the FASTA (their 10-base / 100-ALT example). A per-line maximum is a harder definition. **Fix:** optional. Keep the full square for margin, or divide it by 2.

`splits(argv)` is the right condition. Keep it. Every spelling `Args.parse` accepts (`-m -any`, `-m -both`, `-m -`, and the glued `-m-any`, `-m-both`, `-m-`) sets `Sci.split`, and no accepted word clears it, so a repeated `-m` stays on when the line parses. A bad value, a final `-m` with no value, or any other usage error makes `Args.parse` return `None`; `law usage` then never drives, so the extra term is 0. Adding the square on every command line would loosen `law machine` for runs that do not split. On those runs the present bound meets the budget exactly, and the consent is only for `-m`.

`docs/LAWS.md` states `machine` as output, messages and exit code. It does not give the formula, so it stays. The formula is only the fuel and the read limit in `launch`. A larger fuel under `-m` leaves a finished run's output, messages and exit code as they are. With `splits` false the added term is 0, so a run without `-m` has the same bound it has now.
